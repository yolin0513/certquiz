# I. 原創題的真值（2026-10-08，出題前定案）

## 問題

TABF 那批有官方答案卷當真值；**原創題沒有外部答案可以核對**。錯的練習題跟錯位的答案一樣危險——使用者會把錯的背下來。所以出題前先決定：用什麼當真值。

## 決定：真值在官方文件上，不在出題者的記憶裡

**每一題的正確答案，必須能從它引用的那段官方文件原文直接讀出來。引用不到，就不收這一題。**

### 每一題強制要有的欄位（`scripts/build_data.py` 缺一個就拒絕建置）

| 欄位 | 內容 | 檢查 |
|---|---|---|
| `objective` | 對應的官方大綱節次（例如 `B.3`） | 必須是 `data/src/certs.json` 裡列的 11 個節次之一；節次名稱已逐字對過官方 study guide（Skills measured as of July 20, 2026） |
| `basis` | 官方文件網址 | 必須是 `https://learn.microsoft.com/en-us/...` |
| `basis_quote` | 從那一頁**逐字摘錄**的英文原文（20～400 字元）。**只留本機**：草稿檔或 `data/local/basis/*.txt`，公開題目檔不得含（`build_data.py` 會擋） | `verify_basis.py` 抓那一頁，確認逐字出現 |
| `basis_anchor` | 原文所在章節的錨點（例如 `#lock-inheritance`；頁首導言用 `#`） | 原文必須落在這一節，否則「錨點過時」 |
| `basis_section` | 那一節的標題（錨點是 `#` 時可省略） | 給人找用 |
| `basis_hash`、`basis_len` | 原文空白正規化後的 sha256 與字數 | 沒有原文時，用這兩個在那一節逐格比對；有原文時必須跟原文一致 |
| `explain` | 繁中解析：說明為什麼正解對、其他選項為什麼錯，並指回那段原文 | 必填 |
| `source` | `original-ai` | AZ-900 只收 `original-*` |

### 機器核對：`scripts/verify_basis.py`

- 對每一題：抓 `basis` 的頁面 → 取出可見文字（去掉 script／style）→ 空白正規化。
  - **有原文**（草稿、或本機原文庫）：原文逐字在頁上，且雜湊、字數跟題目檔記的一致。
  - **沒有原文**（公開題目檔、別人 clone 下來）：在錨點那一節用「字數＋雜湊」逐格比對；那一節找不到再找整頁。
  - 原文在頁上但不在標記的章節 → **錨點過時**；整頁都找不到 → **依據失效**。
- **授權**：頁面中繼資料 `original_content_git_url` 指向原始 repo（私有的 `-pr` 對應去掉 `-pr` 的公開版），公開版要有這一頁的原始檔，而且那個 repo 的法律聲明（`ThirdPartyNotices.md`，沒有就看 `LICENSE`）授權文件內容 CC BY 4.0。**查不到就不通過**（「查不到不等於可以」）。限制：只核對「原始檔存在」，沒有逐題核對原始檔裡有那句原文（2026-10-08 抽一題核對過）。
- **驗尺**（常設規則 14、16）：逐字比對、雜湊比對各一組正反對照，同一次執行裡先驗。
- 輸出「核對了幾題／應該核對幾題」（常設規則 15），「應該」直接數原始檔的 `=== az900-` 行；也印「幾題逐字比對、幾題只靠雜湊」與「授權查得到的頁面 x／y」。
- 抓不到頁面、或一題都沒讀到，結束碼 2——抓不到不等於依據失效。
- 離線測試 `scripts/test_verify_basis.py`（15 項，已加進推送閘門）。對檢查器本身做過三個突變（拿掉錨點檢查、拿掉授權檢查、整頁找不到也不報失效），測試都變紅且理由對。

### 有裁量的授權判斷：entra-docs（2026-10-08，這是判斷，不是查到的事實）

Entra 的頁面（條件式存取、Domain Services、MFA、External ID、Entra ID、SSO）來自公開 repo `MicrosoftDocs/entra-docs`。這個 repo 的兩份文件說法不一致：

| 文件 | 內容（2026-10-08 讀取） |
|---|---|
| `LICENSE` | 第一行是 `MIT License`，全文是 MIT 授權（和同 repo 的 `LICENSE-CODE` 一樣是 MIT，但文字版本不同） |
| `ThirdPartyNotices.md`（Legal Notices） | 寫明 Microsoft 與貢獻者「grant you a license to the Microsoft documentation」（授權文件內容）採 CC BY 4.0，並說「see the LICENSE file」；程式碼則採 MIT、見 `LICENSE-CODE` |

**採用法律聲明（CC BY 4.0）的理由**：
1. 法律聲明是**分開處理「文件」與「程式碼」**的那一份，而且明文指定文件內容的授權；`LICENSE` 檔沒有區分對象。
2. 其他 MicrosoftDocs repo（azure-docs、azure-monitor-docs 等）都是 `LICENSE`＝CC BY 4.0、`LICENSE-CODE`＝MIT，法律聲明的文字相同。entra-docs 的法律聲明說「見 LICENSE 檔」，但 `LICENSE` 卻是 MIT——看起來是 `LICENSE` 檔放錯，而不是文件內容改採 MIT。
3. **兩種讀法對本專案的結論相同**：本專案公開的只有網址、章節錨點、章節標題與原文雜湊，原文只留本機；不論內容授權是 CC BY 4.0 還是 MIT，這樣的使用都在允許範圍內。所以這個判斷錯了的後果小。

**複查方式**：重讀上面兩份文件；若 Microsoft 修正了 `LICENSE`（改成 CC BY 4.0）或修改法律聲明，更新這一段。`verify_basis.py` 的授權檢查是先看 `ThirdPartyNotices.md`、再看 `LICENSE`，所以這個判斷也寫在程式裡——要改判斷就要改程式。

### 定期檢查：依據會失效

```
python scripts/verify_basis.py --recheck
```

核對 `data/src/az900/` 與 `data/local/draft/az900/` 的全部題目，報出「依據失效／錨點過時／授權查不到」的題號。

**為什麼要跑**：官方文件會改版——原文可能被改寫、搬到別的章節、或整段刪掉；產品本身也會改名或改行為。題目當初對，不代表現在還對。不跑的話，題目會在沒有人知道的情況下繼續教舊的（或錯的）東西。

**什麼時候跑**：不自動跑。每次加新一批題目前跑一次；平常每隔幾個月跑一次。報出來的題目先停用（標 `status: retired` 或改題），重新核對官方文件後再決定改題還是撤題。

### 草稿流程

1. 題目先寫在 `data/local/draft/<證照>/*.txt`（`data/local/` 被 .gitignore 擋住，不會進 repo）。
2. `python scripts/verify_basis.py --fill data/local/draft/az900/<檔>`：依原文算出錨點、章節、雜湊、字數，寫回草稿。
3. `python scripts/build_data.py --draft data/local/draft`：用公開題庫的規則檢查，另外要求草稿有原文、雜湊對得上（注意給的是 `<證照>` 的上一層；0 題會結束碼 2）。
4. `python scripts/verify_basis.py data/local/draft`：連到 learn.microsoft.com 與 GitHub 核對依據與授權（開發時才連，App 不連；STATUS 規則 9 的界線）。
5. 人工核對 → 交給 Dispatch／使用者抽查 → 同意後搬進 repo：題目檔去掉 `basis_quote` 放 `data/src/az900/`，原文另存 `data/local/basis/az900.txt`（`=== id` ＋ `basis_quote:`）。
- 頁面改版、引用對不上時：那一題標「依據失效」，不出題，直到有人重新核對。

### 人工核對（機器只能證明「引用真的在文件上」，不能證明「題目問得對」）

每一題出題者都要逐項確認：
1. 正解能從引用原文**直接**讀出來，不需要額外推論或記憶。
2. 每一個錯誤選項，都能用那段原文（或同一頁的其他段落）判斷為錯；**判斷不了的選項不能放**——否則可能出現兩個正解。
   - **情境題例外**（2026-10-08 起，配合 Dispatch 要加情境題）：「某公司需要 X，應該用哪個服務」的錯誤選項是其他服務，它們的定義常在別的官方頁面上。這時允許用別頁排除，但解析要寫出是哪個服務、它的定義是什麼。**這部分只有人工核對、沒有機器核對**——`verify_basis.py` 只核對正解那一段引用。
   - 出錯誤選項前先查「這個服務的文件裡有沒有提到它也能做這件事」。例：Data Box 那題沒有放 Azure Migrate，因為 Azure Migrate 的文件寫它也支援用 Data Box 做離線遷移，放了會變成兩個正解。
3. 題幹不含「通常」「大多」這類讓答案模糊的字。
4. 繁中題幹＋英文術語並列（例如「可用性區域（Availability Zone）」）。

每一批交給 Dispatch／使用者抽查之後，才進 repo（Dispatch 2026-10-08：新增題目檔進 repo 要先問）。

### 出題時踩過的判斷（2026-10-08，第 4、5 批）

- **官方文件彼此矛盾的點不出題**：Azure 免費帳戶「永遠免費的服務」數量，一個訓練單元寫 65 個以上、另一個寫 25 個以上。兩者都是官方原文，答案取決於引哪一頁，這種點不當題目（真值不唯一）。
- **「只是一部分」的原文不能拿來排除選項**：原文寫「X、Y、Z are just some of the…」時，清單是開放的，不能說「不在清單上的就錯」。這種題的錯誤選項要用同一頁別處明說屬於其他類別的東西（例：效能可預測性那題，錯誤選項改成同一頁明說屬於「成本」可預測性的定價計算機）。
- **錯誤選項不能是真實存在、只是原文沒提的東西**：水平擴展那題原本有「預測擴展（predictive scaling）」當錯誤選項，但 Azure 真的有 predictive autoscale，懂的人會被誤導，改成同一頁定義過的其他概念。
- **解析裡出現「原文沒有…」「沒有依據」就是弱排除的訊號**：收尾時用這兩個詞搜尋全部 200 題，找到的都改成「同一頁的某句話怎麼說」或改掉選項。
- **調換選項平衡正解位置時**，解析裡寫了「選項 N」的題目要連解析一起改；依數字排序的選項（例：2／4／6 層）不調。

## 什麼不能用（NDA 與版權）

- **不參考、不改寫、不重組任何微軟官方練習題（Practice Assessment）、考後回憶、dump、MeasureUp 或任何第三方題庫的題目。**題目只從官方大綱（考什麼）與官方技術文件（內容是什麼）自己出。
- 引用原文保持短（一兩句），並附來源網址；解析用自己的話寫，不整段貼文件。

## 畫面上的標示

- 每題標「原創練習題，不是考題」與大綱節次。
- 作答後顯示依據網址＋章節錨點＋章節標題（例如 `…/lock-resources#lock-inheritance（章節：Lock inheritance）`），**不顯示原文**。網址**只以文字顯示、不做成可點的連結**：做成連結等於新增對外連線，依 Dispatch 2026-10-08 的授權範圍要先問。

## 已知限制

- 真值是「出題當時的官方文件」。Azure 產品與文件會變，`verify_basis.py` 只能抓到「引用文字從頁面上消失」，抓不到「文字還在但意思被別段推翻」。
- 機器核對證明引用是真的；題目問法是否恰當、錯誤選項是否真的錯，靠人工核對與抽查。

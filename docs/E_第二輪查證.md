### 權重

| AI-900 | AI-901 |
|---|---|
| AI 工作負載與考量 15–20% | **AI 概念與能力 40–45%** |
| Azure 機器學習基本原理 15–20% | （拿掉） |
| 電腦視覺 15–20% | （併進概念與實作） |

### 考生描述（原文）

- AI-900：「Data science and software engineering experience are not required.」
- AI-901：「You also need knowledge of Python coding syntax and programming techniques, and you should be familiar with Azure resources.」；另註「You should be familiar with REST APIs, SDKs, and CLIs.」

### 保留的

- 負責任 AI 六原則（公平、可靠與安全、隱私與安全性、包容、透明、問責），**逐字相同**。
- 文字分析：關鍵字擷取、實體辨識、情感分析。
- 語音辨識與語音合成。
- 電腦視覺（改成較籠統的「features and capabilities」）。
- 生成式 AI 的運作與情境。

### 拿掉的

- 「Azure 機器學習基本原理」整個大項：迴歸、分類、分群、深度學習、Transformer 架構、資料集的特徵與標籤、訓練集與驗證集、自動化機器學習、資料與運算服務、Azure ML 的模型管理與部署。
- 電腦視覺細項：影像分類、物件偵測、OCR、臉部偵測與分析；點名的 Azure AI Vision、Azure AI Face 服務。
- NLP 細項：語言模型、翻譯；點名的 Azure AI Language、Azure AI Speech 服務（AI-901 改點名「Azure Speech in Foundry Tools」）。
- 生成式 AI 點名的 Azure OpenAI Service、模型目錄。
- 文件處理（document processing）：改成「資訊擷取」並擴大範圍。

### 新增的，以及要不要動手

| 新增項目 | 寫程式（Python SDK） | 操作 Foundry 介面 | 依據 |
|---|---|---|---|
| agentic AI 情境；依能力選模型；部署選項與設定參數；摘要；影像生成模型；從音訊與影片擷取資訊 | 否 | 否 | 觀念題（「Identify」「Describe」） |
| 撰寫有效的 system／user prompt | 否 | 可能 | 原文「Create effective system and user prompts」 |
| 在 Foundry 入口網站部署模型並互動 | 否 | **是** | 原文寫 in the Foundry portal |
| 用 Foundry SDK 寫輕量聊天用戶端 | **是** | — | 原文寫 by using the Foundry SDK |
| 在入口網站建立並測試單一 agent | 否 | **是** | 原文寫 in the Foundry portal |
| 寫 agent 的輕量用戶端程式 | **是** | — | 原文寫 client application |
| 寫含文字分析、視覺、資訊擷取的輕量程式（3 項） | **是** | — | 原文寫 Build a lightweight application |
| 用 Azure Speech in Foundry Tools 寫輕量程式 | **是** | — | 同上 |
| 用部署好的多模態模型回應語音提示、解讀影像輸入 | →推論兩者都有 | →推論兩者都有 | 原文只寫 by using a deployed multimodal model |

### 一句話結論

對非資訊本科的考生：**AI-900 背觀念就能考；AI-901 有一半以上的分數要求看得懂 Python SDK 程式碼、實際操作過 Foundry——差距在「有沒有動手經驗」，不在觀念深度（機器學習理論反而拿掉了）。**

補充（→推論）：微軟不公布個別考試的題型，所謂「實作」在考場上多半是看程式碼、選正確的呼叫方式或設定，不一定真的要寫完整程式。但要準備，最好開一個 Azure 帳號實際做過一遍。**開 Azure 帳號需要註冊和信用卡，是使用者要決定的事**；App 的選擇題練不到動手的部分。

## 5. 部署：repo 不公開、又要是手機能開的 PWA

先講結論前提：**repo 不公開，不等於網站不公開。** 三條路的網站本身都是公開網址；要讓網站也不公開，得另外加門禁。

### 已查證的條件

- **Service Worker 要 HTTPS**：MDN 原文「Service workers are restricted to running across HTTPS for security reasons」，`localhost` 是唯一例外〔原文〕https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers 。沒有 Service Worker 就不能離線、不能當 PWA 安裝。
- **GitHub Pages**（2026-10-08 補讀現行文件，〔原文〕）：
  - 「GitHub Pages is available in public repositories with GitHub Free and GitHub Free for organizations, and in public and private repositories with GitHub Pro, GitHub Team, GitHub Enterprise Cloud, and GitHub Enterprise Server.」https://docs.github.com/en/pages/getting-started-with-github-pages/about-github-pages
  - 「GitHub Pages sites are publicly available on the internet, even if the repository for the site is private (if your plan or organization allows it).」https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site
  - 「To publish a GitHub Pages site privately, you need to have an organization account.」https://docs.github.com/en/get-started/learning-about-github/githubs-plans
  -使用者目前的 GitHub 方案我沒查；Pro 的價格沒查。
- **Cloudflare**（這台機器上實測，唯讀）：
  - `wrangler whoami`：**已登入** 使用者的帳號（OAuth）。憑證檔裡的 access token 已在 2026-10-07 到期，但有 refresh token，執行時自動換新了。權限含 `pages (write)`、`workers (write)`。
  - wrangler 沒裝在全域；RentCheck 專案裡有 4.131.0（我用它跑 `whoami`，工作目錄放在 scratchpad，沒有寫 RentCheck）。
  - **RentCheck 已有前例**（只讀其 STATUS）：Cloudflare 已把 Pages 併進 Workers，`wrangler pages project create` 會失敗；改用 Workers 靜態資產（`wrangler.jsonc` 只上傳 `dist/`）＋`scripts/deploy.sh`。網址是 `<名稱>.<帳號子網域>.workers.dev`。
  - Cloudflare 官方文件：workers.dev 啟用後「your workers.dev URL is available publicly」；可用 Cloudflare Access 要求訪客登入〔原文〕https://developers.cloudflare.com/workers/configuration/routing/workers-dev/
  - Access 免費方案上限 50 人〔摘要：Cloudflare 2020 年部落格 https://blog.cloudflare.com/teams-plans ；現行條件未查證〕。

### 三條路

| | A. Cloudflare Workers 靜態資產（建議） | B. GitHub Pro＋私有 repo＋Pages | C. 不上網：本機或區域網路 |
|---|---|---|---|
| 程式碼 | GitHub 私有 repo（免費帳號可開）或只在本機 git | 私有 repo | 本機 |
| 網站可見度 | 公開網址；要私人就加 Cloudflare Access | **仍是公開網址**〔原文〕；個人帳號沒有私人發布，要組織帳號 | 只有同一個區域網路連得到 |
| 費用 | 免費額度內 0 | **要付費**（金額未查證） | 0 |
| 手機 PWA（離線、安裝） | 可以 | 可以 | **基本上不行**：手機用 `http://192.168.x.x` 連線不是安全來源，Service Worker 不會註冊；要做到得在手機安裝自簽憑證 |
| 更新 | 本機一行部署（照 RentCheck 的 `deploy.sh`，先跑測試與個資掃描再上傳） | `git push` | 每次都要開電腦、手機要在同一個網路 |
| 主要代價 | 多一個平台；網址跟其他 App 不同來源（各 App 的本機資料本來就分開，影響不大） | 花錢卻沒換到網站不公開 | 失去 PWA 的離線與安裝，等於只是網頁 |

### 建議：A，TABF 官方題不上傳

- 部署出去的只有練習功能和原創題。TABF 官方題由使用者在 App 裡「匯入」到自己手機，**不上傳到任何伺服器**（符合「只在使用者自己的裝置上用」）。代價：每換一台手機或清掉瀏覽器資料，就要重新匯入一次。
- 要讓網站本身也只有他能開：在 A 前面加 Cloudflare Access。代價是要改 Cloudflare 帳號設定（要他同意）；推論登入過期時，PWA 在背景抓更新可能被擋，要實測。
- **沒有部署任何東西，也沒有建立任何遠端 repo。** 建 GitHub 私有 repo、第一次部署、加 Access，都要先問 使用者。

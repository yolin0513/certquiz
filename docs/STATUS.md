## 設計前提：本機自用 vs 公開散布（接手前一定要先懂）

這個 repo 與網站都是**公開**的（GitHub Pages）。TABF 官方試題的處理方式由這條界線決定：

| | 本機自用 ✅ 做 | 公開散布 ❌ 不做 |
|---|---|---|
| 內容 | 在 使用者的電腦上把官方 PDF 轉成題庫檔，他匯入**自己的手機** | 題庫檔進 repo、上網站、內建在 App |
| 放哪 | `refs/`（PDF）、`data/local/`（題庫檔），`.gitignore`＋commit 前自查雙重擋 | — |
| 誰拿得到 | 只有他 | 任何人 |

- 轉檔**腳本**進 repo（不含題目內容），換電腦可重跑；**題庫檔**永遠不進 repo。
- 公開網站上只有練習引擎和原創題。
- 著作權法第 9 條第 1 項第 5 款「依法令舉行之考試試題」是否適用於這張測驗：智慧局函釋（電子郵件1041201）以本測驗的法源為例、條件式肯定，但自稱非主管機關、建議洽金管會；**不是確定結論**（見 `H_TABF題庫與法律問題.md`）。**因為題目不散布，這個法律問題對本專案不構成風險；把題目改成公開，要 使用者本人看過依據強度後拍板。**

## 常設規則（第一階段起生效）

1. 產出一律繁體中文；思考不限語言。
2. **不得使用互動式提示框**（AskUserQuestion 之類）；要使用者決定的事用純文字列選項、代價、建議，然後停下等。
3. 要花錢、要註冊帳號、要用機構訂閱 → 停下來問。不繞過機器人驗證、不抓需要登入的內容。
4. 只在本工作目錄寫檔；`D:` 下其他專案一律唯讀（可以讀、可以執行它們裝好的工具，但工作目錄不放在那裡、不寫進去）。
5. **題目來源鐵則**：
   - 不收任何微軟真實考題、考後回憶、dump；微軟題只能是原創。
   - 第三方題庫（書商、補習班、阿摩、MeasureUp）不抓、不存、不複製。
   - **TABF 官方題只放 `refs/` 與 `data/local/`**（不進 repo、不部署、不上傳任何伺服器），由使用者在 App 內匯入自己的手機。
   - AZ-900 題目的 `source` 只能是 `original-*`；解析的依據放 Learn 連結，不貼原文段落；畫面標「練習題，不是考題」。
   - 下載任何檔案前要使用者同意；只從官方網域下載。
6. **題目 id 寫死在原始檔、永不改、永不重用**；刪題改標 `retired`（見 `docs/D_架構草案.md` §0、§2）。
7. 回報分開寫「實際查到的」與「推論的」，查不到寫「在已檢索範圍內未見（檢索了 X）」。
8. **使用者的說法跟官方原文不一致時**，兩邊都寫出來、標明哪個有原文，讓使用者自己對照，不要直接選一邊照做。
9. 部署、建立遠端 repo、第一次 push、改雲端帳號設定，一律先問。
10. **兩種來源分開管**：`refs/tabf/`＝本 Session 從官網下載（可逐位元組對官網）；`refs/user/`＝使用者提供（記錄使用者說的來源、檔案判斷的來源、兩者對不對得上）。使用者提供的題目轉出來標 `source: user-import`、id 用 `u<期>`（例如 `bic-law-u39-001`），**不覆蓋官網那批**；同一期同一題兩邊都有時，**答案一律以官網 PDF 為準**，不一致的題號列給使用者看。判斷不出來源的標「來源不明」；看得出是第三方整理或轉載的，只供使用者本人使用、不轉成要散布的題庫、不入庫，並在回報裡點名。
11. **repo 會公開**：防護設在 commit 之前。commit 前自查（pre-commit）與 push 前歷史掃描（pre-push）不得停用；**新 clone 要先下 `git config core.hooksPath .githooks`**（本機設定不跟 repo 走）。改過 `scripts/selfcheck.py` 或 `.gitignore`，要跑 `python scripts/selfcheck.py --selftest` 全部符合才能 commit。不用 `--no-verify`。
12. 作答紀錄只存在使用者手機的 IndexedDB，不得有任何上傳；第二階段用 CSP＋靜態檢查＋瀏覽器網路實測三層保證（G M1-8）。
13. **「擋下」要核對理由，不能只看回傳值**（2026-10-08 起）。
    - **起因**：pushsafe 驗法在 Windows 上叫到 System32 的 WSL bash（沒裝發行版），五個情境全都沒跑起來；其中四個「應該擋下」的情境因為**失敗的回傳值剛好等於擋下的回傳值**，被算成通過。也就是**閘門完全沒運作的時候，它的自我測試顯示全綠**——這是最糟的失效：不是沒擋，是沒擋還告訴你擋住了。
    - **理由**：只看「有沒有失敗」分不出「規則擋下」和「程式根本沒跑」；要看「擋下的理由是不是我造的那一個」。
    - **做法**：凡是「預期會擋下／會失敗」的測試情境，判定必須同時核對①回傳值、②行首判定行裡的**指定理由**（點名的規則、題號、檔名）、③副作用的狀態（例如假遠端沒變、沒寫出檔）。沒有判定行就判「情境未成立」，不算通過。量測工具（網路監測、掃描器）要先用已知樣本證明抓得到，再拿它下「沒有發生」的結論——**抓不到和沒有發生，在輸出上長得一樣**。
    - Windows 上從 Python／node 叫 bash 一律用 `shutil.which("bash")` 的完整路徑（Git Bash）。
    - 尚未補理由核對的檢查清單見「已知不一致與技術債」。
14. 量測先驗尺：任何「沒有 X」的結論（沒有外部請求、沒有洩漏、沒有命中），量測工具都要在同一次執行裡先用一個刻意造出的 X 證明抓得到；驗尺失敗就整個中止，不下結論。

## 踩過的坑

- **網頁抓取工具讀 PDF 會自動把檔案存到 session 暫存區**（2026-10-08）。研究第三方網站時這等於「存了第三方題目」。以後研究階段讀到 PDF 後要檢查並清掉，或避免讀第三方 PDF。
- **微軟的考試頁有新舊說法並存**：AI-901 考試頁的簡短描述還沿用 AI-900 的舊文字；AI-901 證照頁說 learning path「not yet available」，課程頁卻列了 learning path。以 study guide 為準。
- **TABF 網站對 Python 3.13 的憑證檢查不過**（`Missing Subject Key Identifier`），curl 可以。不要為此關掉憑證驗證；用 curl 收發、Python 只解析。
- **TABF 的簡章下載是 ASP.NET postback**：先 GET 頁面拿隱藏欄位，再 POST `__EVENTTARGET=ctl00$ContentPlaceHolder1$RPT_Brief$ctl0{0|1}$lbRPT_Brief`（0＝筆試、1＝電腦應試）。場次表翻頁可直接用 `LicenseExamList.aspx?P=<頁>&ExamCode=051&ShowFull=1`。
- **Windows 的 git 預設不分大小寫**（`core.ignorecase=true`）：`.gitignore` 的 `*.PDF` 也擋得住 `x.pdf`，所以「只拿掉 `*.pdf`」這個突變不會紅，要兩行都拿掉才是真的洞（2026-10-08 突變測試時發現）。
- **自查程式自己會被自己擋**：註解裡寫路徑範例（磁碟代號＋Users＋名字之類）就觸發 R4。解法是改寫成文字描述、測試樣本在執行時才組字串；**不要用開例外的方式解**，例外就是洞。
- **TABF 簡章寫的法源條號是舊的**：簡章與 FAQ 寫「實施辦法第 24 條第 1 項第 3 款」，現行（115-05-06 修正）第 24 條是資訊安全；測驗規定在**第 41 條第 1 項第 3 款**。引用法條一律查全國法規資料庫現行版。
- **TABF 試卷是 A3 雙欄**：`pdftotext` 直接抽，題號左右交錯（14 15 1 16 2…）；要逐頁切欄。
- **pdftotext 是 xpdf 4.00（Git for Windows 內附），不是 poppler**：沒有 `-x/-y` 裁切、沒有 `-bbox`。TABF 雙欄試卷用 `-raw`（照內容流順序，剛好是左欄再右欄）可以拿到 1..N 連續題號；`-layout` 依字元位置切欄不可靠（全形字與空白寬度不同）。題號偶爾緊接在換頁符號 `\f` 後面，比對要容許。
- **`pdftotext -table` 讀答案卷會整欄錯位一列**（表頭那列吃到第 1 題的答案）——答案錯位在真實工具裡就會發生，所以答案一定要兩條獨立讀法逐題比對（`-raw` 逐列、`-simple` 依水平位置）。
- **heredoc 裡用 Python 做字串取代，`\n` 很容易被寫成真的換行**（2026-10-08 踩了三次，把程式檔寫壞，其中兩次是先寫檔才編譯；連這一條紀錄本身和上一條的 `\f` 都被寫壞過）。**改程式碼一律用 Edit 工具。**非用腳本不可時，用 `chr(10)`、`chr(92)` 組字，並且先編譯檢查、通過才寫檔。
- **重跑抽樣腳本會蓋掉已填的核對紀錄**（2026-10-08：為了確認可重現而重跑 `sample_check.py`，把 40 題的核對紀錄蓋掉，事後依原紀錄補回並在檔內註明）。已改成檔案存在就不覆寫，要重寫須加 `--force`；兩向都在暫存複本驗過。
- **Windows 上 Python 用 subprocess 叫 `bash` 會找到 System32 的 WSL bash**（沒裝發行版就跑不起來；`shutil.which` 卻回 Git Bash，兩者搜尋順序不同）。2026-10-08 pushsafe 驗法五個情境全都沒跑起來，其中四個「擋下」的情境因為也回 1 而顯示通過——**只看回傳值的測試會把當掉算成擋下**。已改成用完整路徑，並要求每個擋下都附指定理由。
- **GitHub Pages 專案站的 robots.txt 無效**：專案站在子路徑（`…github.io/<repo>/`），搜尋引擎只讀網域根目錄的 robots.txt。本專案不放 robots.txt，靠 `index.html` 的 noindex meta；GitHub Pages 也不能設 X-Robots-Tag 標頭。
- **Cloudflare Pages 已併進 Workers**（RentCheck 的經驗）：`wrangler pages project create` 會失敗，要用 `wrangler.jsonc` 的 Workers 靜態資產＋`wrangler deploy`。

# G. 第二階段計畫（**草案，等確認後才動手寫 App 程式**）

- 2026-10-08。依使用者的決定：範圍是**一般金融組**，以**電腦應試**的節奏為準（場次幾乎天天有 → 以「早一點有東西可以練」為優先）、**先做 AZ-900**（AI 那張先不做）、部署 **GitHub Pages（公開 repo）**。
- 架構照 JLPT_App（原生 JS＋IndexedDB＋Service Worker、無框架、題庫用 Python 腳本建置），細節見 `D_架構草案.md`；公開 repo 的防護見 `F_公開repo的影響與防護.md`。
- **不自己建遠端 repo、不做第一次 push**：那兩步到了會先問。
- **設計前提**：TABF 題目是「本機自用」，不是「公開散布」——見 `H_TABF題庫與法律問題.md` 與 STATUS 開頭。

## 2. 里程碑（照「早一點能練」排）

### M1｜內控可以在手機上練（最優先）

| # | 工作 | 說明 | 產出 |
|---|---|---|---|
| 1 | 專案骨架 | `CLAUDE.md`（常設規則，照 JLPT 格式）、目錄結構、`index.html`、`manifest.webmanifest`、`sw.js`、圖示 | 可開啟的空殼 |
| 2 | 題庫格式與建置 | `scripts/build_data.py`：一題一區塊、id 寫死、檢查（id 重複／答案不在選項內／章節不存在／法規題缺基準日）、全部寫成 .tmp 再一起換上（JLPT 的 `commit_outputs` 做法） | `data/<證照>/*.json`、`manifest.json` |
| 3 | 證照與章節定義 | `bic`（內控一般金融）：兩科；章節照簡章的命題範圍——法規分「基本法令及行政規章」「相關函令」，實務分「內控與內稽制度」＋11 種業務查核。`az900`：照官方大綱三大領域 | `data/src/<證照>/cert.txt` |
| 4 | **TABF 題庫轉檔（輸出不進 repo）** | `scripts/import_tabf.py`：用本機已有的 `pdftotext`（Git for Windows 內附，不必安裝新套件）讀 PDF。**難點**：試卷是 A3 雙欄，直接抽字題號會左右交錯（實測第 49 期法規卷）→ 要逐頁切左右兩欄分別抽。答案卷是文字表格，可直接讀。**腳本入庫（不含題目內容），換電腦可重跑；輸出到 `data/local/bic/`（`.gitignore` 擋、commit 前自查也擋），不進 repo、不部署、App 不內建。** id 用期別＋題號（`bic-law-t49-012`），重跑時同一題 id 不變；`law_as_of` 填該期測驗日 | 390 題（本機） |
| 5 | 轉檔核對 | 程式核對：每期法規 50 題、實務 80 題，每題 4 個選項，答案 1～4；**人工核對**：每期抽樣對照 PDF（題幹斷行、錯字、選項錯位）。抽樣數照 JLPT 慣例至少 40 題，使用者要不要親自抽，見 §4 | 核對紀錄寫進 STATUS |
| 6 | 匯入包與匯入步驟 | 把 `data/local/` 的題目打包成一個檔（JSON，約 140 KB；QR 要 16～48 張，不採用，見 H），使用者用 LINE／雲端硬碟傳到手機，在 App「設定 → 匯入題目」選檔。題目只存在手機的 IndexedDB；同一檔重匯不重複。給他的步驟：`docs/匯入步驟_TABF題庫.md`（實機走過再定稿） | 匯入包（本機）＋匯入功能＋步驟文件 |
| 7 | 練習引擎（最小版） | 首頁選證照 → 選科目／章節 → 出題 → 作答立即顯示對錯、正解、來源與法規基準日；錯題本；作答紀錄（`attempts`、`progress`、`mistakes`） | 能練 |
| 8 | 隱私保證 | CSP `connect-src 'self'`；靜態檢查（禁止 POST／`sendBeacon`／外部網址）；瀏覽器實測整輪練習的網路請求全為同網站 GET，並用假樣本證明測試會紅 | 測試 |
| 9 | 推送閘門 | `scripts/pushsafe.sh`：先跑 `selfcheck.py --selftest` 與 `--history`、測試全過才 push（JLPT 的做法：推送一律走它，不直接 `git push`） | 腳本＋驗法 |
| 10 | **建遠端 repo、第一次 push、開 Pages** | **先問 使用者**：repo 名稱、第一次 commit 前文件要不要去掉工作相關描述（F §3）、要不要加 noindex | 手機可開的網址 |

### M2｜內控練得更像考試

- 模擬考：法規 50 題／60 分鐘、實務 80 題／90 分鐘，每科 70 分及格，作答中不顯示對錯（照電腦應試的節奏）。
- SRS 排程（沿用 JLPT 的 Leitner 盒）、統計頁（各章節答對率、弱點章節）。
- 標記功能：「這題法規可能已修」「答案有疑問」。
- 備份匯出／匯入（帶 `idScheme`、`dataVersion`）。

### M3｜AZ-900 原創題

- 第一批（建議 60 題，三大領域依權重分配：雲端概念 ~17、架構與服務 ~23、管理與治理 ~20），之後每批 40～60 題，目標 200～300 題。
- 每題：`source: original-ai`、`basis` 放 Microsoft Learn 文件連結、解析。建置檢查：AZ-900 題目的 `source` 不是 `original-*` 就拒絕。
- 題型：單選、複選、Yes/No 題組（`yn-set`）；拖放、Hot area 不做。
- 每批 Claude 先自查（對照 Learn 文件），再給使用者抽查。
- 畫面標「練習題，不是考題」；首頁寫明非 Microsoft 官方。

### M4｜內控原創題（補解析、補現行法規）

- TABF 官方答案卷只有正解、沒有解析；依法規條文原創題補量、補解析，附條號與法規版本日期。排在 M3 之後，或視使用者需要提前。

## 4. 開工前要使用者決定的事

1. **AZ-900 題目用什麼語言？**
   - (a) 繁體中文題幹＋英文術語並列，例如「可用性區域（Availability Zone）」（建議：考試有繁中版，術語兩種都認得最保險）
   - (b) 全英文（照英文版考試）
   - (c) 全繁中
2. **TABF 轉檔的人工核對**：使用者 要不要親自抽查？建議是 Claude 先全量程式核對＋抽 40 題對照 PDF，使用者只抽 10～20 題確認。
3. **第一次 commit 前，文件裡跟他工作有關的描述要不要改成中性寫法？**（F §3；名字照其他 App 前例保留）
4. **網站要不要加 noindex**（不讓搜尋引擎收錄網站；repo 本身擋不掉）？建議加。
5. **確認範圍與順序**：M1（內控能練）→ M2 → M3（AZ-900）→ M4，有沒有要調整。

遠端 repo 與第一次 push 會在 M1-10 另外問，不在這一輪。
